## Ground rules (read before any change)

1. **⛔ Operator-only actions — never perform these yourself:** publishing packages (PyPI/npm), creating or pushing to remote repositories, deploying containers or sites, submitting to the MCP registry, distributing keys, or making any paid model API call. Prepare artifacts and stop. Items below marked ⛔ are operator gates.
2. **All tests stay offline and mocked.** Static scans must make no network calls. Judgment behavior is tested with mocked clients only.
3. **Contracts stay strict.** Every public model derives from `StrictModel` (`extra="forbid"`). Do not loosen input bounds, consent gates (`judgment=true` requires `send_code=true`), redaction, or containment to make a test pass.
4. **Fixtures and goldens change only deliberately.** If a fingerprint or golden changes, regenerate it in the same commit as the behavior change and say why in the commit message.
5. **Docs move with code.** `PROGRESS.md`, `tasks/validation-report.md`, `README.md`, and `CHANGELOG.md` must match the shipped surface in the same commit (see `docs/constitution.md`).
6. **Both platforms matter.** Changes must pass on Windows and POSIX. Avoid chmod-dependent tests; simulate permission errors with mocks.
7. **Version sync.** `pyproject.toml` version, `archagent_audit.__version__`, and `server.json` version must always agree.
8. **No self-approved scope.** New subsystems, data stores, or public endpoints (for example the proposed Firestore access-control plane) require an operator decision recorded in `DECISIONS.md` **before** they may be written into specs or the constitution as approved scope. See Appendix D for items currently awaiting decision.

## Phase 1 — MCP hardening fixes

All in `archagent_audit/mcp_server.py` unless noted. The MCP design (typed dual-mode local/hosted, bounded inputs, containment, real streamable-HTTP lifecycle test) is sound; these are the specific defects found.

- [ ] **1.1 Close the uncontained-singleton footgun.** `server = create_server()` at module scope builds a local-mode server with `workspace_root=None`; its `audit_file`/`audit_repo` tools then call `_contained_path(path, None)`, which applies **no containment** — while `audit_diff_local` falls back to `Path.cwd()`. Make the behavior uniform: in `create_server(mode="local")`, resolve the effective root once as `(workspace_root or Path.cwd()).resolve(strict=True)` and use it for `audit_file_local`, `audit_repo_local`, and `audit_diff_local` alike — or remove the module-level singleton and have tests construct `create_server(mode="local", workspace_root=...)` explicitly. No code path may expose a path-bearing tool without a workspace root.
  - Test: on a default-constructed local server, calling `audit_file` with a path outside the effective root raises "outside the configured workspace root".
- [ ] **1.2 Contain the private-SDK dependency.** `_harden_tool_contracts` mutates FastMCP internals (`mcp._tool_manager._tools`, `tool.fn_metadata.arg_model`) to force `extra="forbid"`. The `mcp>=1.28.1,<1.29` pin mitigates drift but makes upgrades manual. Do all of: (a) check whether the pinned SDK offers a public way to forbid unknown arguments (e.g., strict/validation options on tool registration) and use it if so; (b) otherwise keep the patch but guard it — if the private attributes are missing, raise a clear startup error naming the SDK version, never degrade silently to permissive parsing; (c) add an "MCP SDK upgrade playbook" subsection to `docs/operations.md` (bump pin → run `tests/test_mcp_server.py::test_mcp_rejects_unknown_arguments` as the canary → check this function).
- [ ] **1.3 Hosted abuse and cost controls.** The hosted mode has no rate limiting or per-key quotas, and hosted judgment spends the **operator's** `OPENAI_API_KEY` — bounded per request (6 rule calls, 2,000 output tokens, 30 s timeouts) but unbounded across requests. Add to the hosted stack:
  - Per-key rate limiting in `BearerKeyMiddleware` (in-memory sliding window or token bucket; env-tunable, e.g. `ARCHAGENT_RATE_LIMIT_PER_MINUTE`, default 30; respond 429 with a JSON body). Document that limits are per-instance in stateless mode.
  - A hosted judgment gate: env `ARCHAGENT_HOSTED_JUDGMENT` (default off). When off, hosted tool calls with `judgment=true` return a clear error instead of spending operator credits. Update `deploy/cloud-run-service.yaml` accordingly.
  - Key attribution in logs: include a short prefix of the key's SHA-256 hash (never the token) alongside the correlation id, so per-key behavior is traceable and revocation is informed.
  - Tests: 429 after exceeding the limit; judgment rejected when the gate is off; log line contains hash prefix and no token.
- [ ] **1.4 Remove the vestigial parameters on `check_tool_schema`.** `judgment`/`send_code` do nothing there beyond returning `judgment_status="not-applicable"`. Remove both parameters (pre-release breaking change is acceptable) or implement real judgment for schemas. Update tests and tool docs.
- [ ] **1.5 Version-sync check.** Extend `scripts/compliance.py` to fail if `server.json` version, `pyproject.toml` version, and `archagent_audit.__version__` disagree. Leave adding a hosted `remotes` entry to `server.json` as a deploy-time step in `docs/operations.md` (the hosted URL does not exist yet).

**Done when:** all new tests pass, no path tool is ever uncontained, hosted judgment is opt-in, and compliance enforces version sync.

## Phase 2 — Reporter correctness

- [ ] **2.1 Escape GitHub workflow commands.** The `github` format (currently inline in `cli.py`, `scan`, `OutputFormat.GITHUB` branch) interpolates `finding.verdict.observed` and properties without escaping. Messages containing `%`, newlines, `::`, commas, or colons will corrupt annotations. Implement proper escaping — message data: `%`→`%25`, `\r`→`%0D`, `\n`→`%0A`; property values additionally `:`→`%3A`, `,`→`%2C` — and move rendering to `archagent_audit/reporters/github.py` for symmetry with the other reporters. Tests must cover hostile messages containing every escaped character.
- [ ] **2.2 SARIF polish** (`archagent_audit/reporters/sarif.py`): a rule with no citation currently serializes `"helpUri": null`; strict consumers reject null-valued properties. Omit absent keys instead. Add `defaultConfiguration: {"level": ...}` per rule from its severity. Add a test asserting the rendered document contains no JSON `null` anywhere, includes `$schema`/`version`/`runs[0].tool.driver.rules`/`results`, uses forward-slash relative URIs, and carries `partialFingerprints.archagentFinding` on every result.

**Done when:** both formats survive hostile finding text and the SARIF test suite passes.

## Appendix D — Decisions pending operator input (do not proceed without them)

- **D.1 Firestore access-control plane: ON HOLD, default = defer to 1.1.** Codex's completion plan proposes replacing the env-var key allowlist with a Firestore-backed system (public `POST /access-requests` endpoint, `/request-access` site page, stored access requests with contact PII, key lifecycle records, transactional usage quotas, an operator admin script, and GCP provisioning). This was **not** approved scope; the plan's instruction to write it into the specs as approved is rescinded per ground rule 8. Unless the operator records approval in `DECISIONS.md`, implement only the minimal hosted controls in item 1.3 (in-memory rate limiting, hosted-judgment env gate, key-prefix log attribution) and keep the existing `ARCHAGENT_API_KEY_HASHES` allowlist. Rationale: the private beta is small, the hackathon deadline dominates, and the full plane roughly doubles remaining work while adding the project's first PII store and a public unauthenticated endpoint. If later approved, note that per-key minute-bucket documents approach Firestore's sustained single-document write limits and should be sharded.
- **D.2 Drizzle/D1 removal: APPROVED as cleanup, Track B only.** Verified in review: `web/db/schema.ts` is intentionally empty (`export {}`), `getDb()` in `web/db/index.ts` is imported by no application code, and no tables or migrations exist. The site does not use a database; removal (packages `drizzle-orm`/`drizzle-kit`, `web/db/`, `web/drizzle.config.ts`, the drizzle copy step in the vite plugin, and related examples) has zero functional effect on the scanner, CLI, MCP, or site pages. Do it in Track B, not before the submission freeze.
- **D.3 Adopted amendments from plan review.** The following Codex-plan improvements are approved and folded in: SARIF upload must complete before the Action fails on findings (Phase 3.3); dependency audit runs against a wheel-installed environment, not the editable checkout (Phase 3/CI); `web/build/sites-vite-plugin.ts` must move out of the gitignored `build/` path before the first push (Phase 0.1 check); CI gains job timeouts, concurrency cancellation, and `tsc --noEmit` for the site.
